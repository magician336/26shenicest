# 八卦小游戏设计方案

## 目标

实现一个双端信息不对称、需要现实沟通的叙事小游戏：Host 在探索阶段触发偷听；Client 根据故事完成“人物—物品”配对；随后 Host 根据照片中的物品线索完成“照片认人”。完成后解锁一张家庭记忆照片。

本方案遵循项目既有约定：一场会话只有一名 Host 和一名 Client；仅 Host 作出权威判定；无失败反馈；小游戏中断后可继续或重新开始。

## 已确认的玩法规则

1. **探索与触发**：Host 操作小岩靠近房门并触发“偷听”；Client 在此阶段等待。
2. **Client 任务**：Client 听三段故事，并在固定 3×3 物品九宫格中完成三组人物—物品配对。
3. **可访问性**：每段故事可无限次播放，并显示与语音一致的大字号原文字幕；字幕不高亮答案。
4. **自动转场**：Client 完成三组配对后，Host 自动淡入老照片并进入照片认人，不需要额外确认按钮。
5. **Host 任务**：Host 将三个姓名标签拖入老照片上预先配置的透明人物投放区。
6. **无失败反馈**：选错物品或投错姓名仅播放轻微反馈并复位，不扣分、不终止、不推进共享进度。
7. **中断恢复**：保存已完成配对与已投放姓名；Host 再次触发时可选择继续或重新开始。

### `BaguaStoryConfig`

使用 ScriptableObject 配置故事与美术资源，避免把人物、字幕、音频或物品对应关系写死在代码中。

```csharp
[CreateAssetMenu]
public class BaguaStoryConfig : ScriptableObject
{
    public string miniGameId;
    public BaguaStoryEntry[] entries;
    public Sprite oldFamilyPhoto;
}

[System.Serializable]
public class BaguaStoryEntry
{
    public string characterId;
    public string displayName;
    public Sprite portrait;
    public AudioClip storyAudio;
    [TextArea] public string subtitle;
    public string correctItemId;
    public Sprite itemSprite;
}
```

### `BaguaGameState`

仅保存需要由 Host 验证、同步与恢复的事实；音频播放进度、按钮缩放和抖动等纯表现不进入网络状态。

```csharp
[System.Serializable]
public class BaguaGameState
{
    public GameplayPhase phase;
    public BaguaStep step;
    public List<string> heardStoryIds;
    public List<string> matchedCharacterIds;
    public List<string> assignedPhotoZoneIds;
    public bool clientComplete;
    public bool hostComplete;
    public bool completed;
}
```

`BaguaStep` 为：`ClientMatchItems`、`HostIdentifyPeople`、`Complete`。

## 网络与权威判定

当前网络桥接层直接同步 `CookingGameState`，在接入八卦小游戏前应泛化为统一快照：

```csharp
[System.Serializable]
public class GameplaySnapshot
{
    public GameplayPhase phase;
    public string miniGameId;
    public CookingGameState cooking;
    public BaguaGameState bagua;
}
```

`FusionGameplayBridge` 只序列化与广播 `GameplaySnapshot`；`SessionGameplayCoordinator` 根据 `miniGameId` 将状态交给做饭或八卦逻辑。这样新小游戏不会再次耦合到 Fusion RPC。

建议新增意图：

- `StartBaguaMiniGame`：仅 Host 可发起。
- `MarkBaguaStoryHeard`：Client 听完一条故事后上送；如需强制先听故事，可作为配对前置条件。
- `MatchBaguaItem`：Client 提交人物 ID 与物品 ID；Host 用 `BaguaStoryConfig` 校验。
- `AssignBaguaPhotoName`：Host 提交照片区域 ID 与姓名 ID；Host 校验正确性。
- `FinishMiniGame`：仅当 Client 与 Host 子任务都完成时生效。

Client 三组配对完成后，Host 将步骤推进为 `HostIdentifyPeople` 并广播快照；Host 的私有 UI 因状态变化自动显示照片。所有无效操作只触发本地反馈，不改变快照。

## UI 实现

### Client：听故事与物品配对

- 左侧显示三张人物卡、声音按钮与大字号字幕区域。
- 点击声音按钮：播放 AudioClip、显示对应字幕、人物卡轻微放大并播放声波动画。
- 右侧为固定 3×3 物品格，使用点击式配对：先选择人物，再选择物品。
- 正确配对后锁定该人物和物品；错误时物品抖动后复位。
- Client 完成后切换为等待页，直到 Host 完成照片认人。

### Host：等待与照片认人

- Client 配对期间显示等待提示。
- 收到 `HostIdentifyPeople` 后以黑场淡入老照片。
- 照片下方显示三个可拖拽姓名标签，复用现有 `DraggableItem` 的拖拽能力。
- 每个透明人物区使用 `PhotoNameDropZone` 检测投放；正确时固定标签，错误时回到原位。

## 探索段与音频

`DoorListeningTrigger` 复用 `IInteractable` 与现有小游戏触发模式，并限制为 Host 可触发：

1. Host 操作小岩从院内走向房门。
2. 依据角色与房门的距离，线性调整室内对话的音量与低通滤波，让声音由模糊渐变为清晰。
3. 进入指定区域时停止角色移动，显示“偷听”。
4. 点击后固定门外偷窥镜头，播放清晰对话和“你听见了他们的故事……”过渡文字。
5. 过渡结束后由 Host 发起 `StartBaguaMiniGame`。

距离效果只用于本地表现；开始小游戏仍以 Host 的权威状态变更为准。

## 存档与奖励

在 `GameProgressSave` 中加入 `BaguaGameState baguaState`，在每个稳定节点保存：开始小游戏、完成一组配对、切换照片认人、完成一组姓名投放、小游戏中断与完成。

完成后：

- 将状态设为 `Complete`，再回到探索阶段。
- 在 `collectedRewardIds` 中加入 `bagua_old_family_photo`。
- 家庭记忆相册根据该 ID 解锁老照片。

## 实施顺序

1. 建立 `BaguaStoryConfig` 与三组故事/物品测试资源。
2. 泛化网络快照和协调器，使做饭与八卦共用 Host 权威同步通道。
3. 实现 `BaguaGameState`、意图验证与中断/恢复。
4. 实现 Client 配对私有 UI。
5. 实现 Host 老照片私有 UI 与姓名投放。
6. 接入房门互动、窥视镜头、距离音频和过渡动画。
7. 接入相册解锁与存档恢复。
8. 在 Editor 中分别验证 Host、Client、断线恢复和全部无效操作路径。

## 验收清单

- Host 以小岩触发偷听，Client 不可触发探索互动。
- Client 可无限次重播每段音频并阅读对应大字幕。
- 只有三个正确人物—物品组合能够推进 Client 进度。
- Client 完成后，Host 自动收到并显示老照片。
- Host 只能以正确姓名完成每个人物区域的投放。
- 任意错误操作无处罚、无中断、无共享状态推进。
- 中断后继续时保留双方已完成进度；重开时清空本小游戏进度。
- 双端状态由 Host 判定并通过 Fusion 同步。
